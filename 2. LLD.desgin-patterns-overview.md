Catergories of Patterns:
1. Creational Patterns
2. Structural Patterns
3. Behavioral Patterns
------------------------------------------------------
1. Creational Patterns:
It controls the creation of objects.
    - Singleton Pattern
    - Factory Pattern
    - Abstract Factory Pattern
    - Builder Pattern
    - Prototype Pattern
    - Object Pool Pattern

2. Structural Patterns:
It focus on, how different classes and objects are arranged together so that larger Problems can be solved in most flexible way.
    - Adapter Pattern
    - Bridge Pattern
    - Composite Pattern
    - Decorator Pattern
    - Facade Pattern
    - Proxy Pattern
    - Flyweight Pattern 

3. Behavioral Patterns:
It focus on, how different objects communicate and interact with each other.
    - Chain of Responsibility Pattern
    - Command Pattern
    - Interpreter Pattern
    - Iterator Pattern
    - Mediator Pattern
    - Memento Pattern
    - Observer Pattern
    - State Pattern
    - Strategy Pattern
    - Template Method Pattern
    - Visitor Pattern
    - Null Object Pattern

Has-a and is-a relationship:

    - Is-a relationship:
        - this is nothing but an inheritance relationship.
        - Example: 
            - two-wheeler is a vehicle
            - four-wheeler is a vehicle
            parent class - vehicle, 
            child class - two-wheeler, four-wheeler with is-a relationship.
            
    -----------------------------------------------------
    
    - Has-a relationship:
        - shows a link between two different Objects.
        - Example:
            - House has rooms.
            - Library has books.
            - School has students.
        Association:
        - weak relationship (aggregation) 
            - existeence of one object does not depend on the other object.
            - Example:
                - Library can exist without books.
                - Books can exist without library.
                public class Library {
                    private List<Book> books;
                }
                here if books are deleted, library still exists.
                and if library is deleted, books are not deleted.
        - strong relationship (composition)
            - existeence of one object depends on the other object.
            - Example:
                - House can not exist without rooms.
                - Rooms can not exist without house.
                public class House {
                    private List<Room> rooms;
                    public House() {
                        this.rooms = new ArrayList<>();
                    }
                    public void addRoom(Room room) {
                        this.rooms.add(room);
                    }
                    public void removeRoom(Room room) {
                        this.rooms.remove(room);
                    }
                    public List<Room> getRooms() {
                        return this.rooms;
                    }
                }
                here if rooms are deleted, house is also deleted.
                and if house is deleted, rooms are also deleted.
