# SOLID Principles

## Overview
- **S**: Single Responsibility Principle
- **O**: Open/Closed Principle
- **L**: Liskov Substitution Principle
- **I**: Interface Segregation Principle
- **D**: Dependency Inversion Principle

---

## Single Responsibility Principle
Only one reason to change.

### Example:

**Wrong way:**
```java
class UserService {
    public void saveUser(String name) {
        // save to database
    }
    public void sendEmail(String email) {
        // send email
    }
}
```

**Correct way:**
```java
class UserService {
    public void saveUser(String name) {
        // save to database
    }
}
class EmailService {
    public void sendEmail(String email) {
        // send email
    }
}
```

## Open/Closed Principle
Open for extension, closed for modification.

**Wrong way:**
```java
class PaymentService {
    public void pay(String type) {
        if (type.equals("credit")) {
            // credit logic
        } else if (type.equals("upi")) {
            // upi logic
        }
    }
}
```

**Correct way:**
```java
interface Payment {
    void pay();
}
class CreditCardPayment implements Payment {
    public void pay() {
        System.out.println("Credit Card Payment");
    }
}
class UPIPayment implements Payment {
    public void pay() {
        System.out.println("UPI Payment");
    }
}
```

## Liskov Substitution Principle
Subclass should replace parent without breaking behavior.

### Example:

**Wrong way:**
```java
class Bird {
    void fly() {}
}
class Ostrich extends Bird {
    void fly() {
        throw new UnsupportedOperationException();
    }
}
```

**Correct way:**
```java
class Bird {}
class FlyingBird extends Bird {
    void fly() {}
}
class Sparrow extends FlyingBird {}
class Ostrich extends Bird {}
```

## Interface Segregation Principle
Clients should not be forced to depend on interfaces they do not use.
Subclasses should not implement all methods of the interface that it does not use.
Divide methods into smaller interfaces.

### Example:

**Wrong way:**
```java
interface Worker {
    void work();
    void eat();
}
```

**Correct way:**
```java
interface Worker {
    void work();
}
interface Eater {
    void eat();
}
class Human implements Worker, Eater {
    public void work() {
        System.out.println("Human is working");
    }
    public void eat() {
        System.out.println("Human is eating");
    }
}
class Robot implements Worker {
    public void work() {
        System.out.println("Robot is working");
    }
}
```

## Dependency Inversion Principle

### Example 1:

**Wrong way:**
```java
class MacBook {
    private final WiredMouse mouse;
    private final WiredKeyBoard keyboard;
    public MacBook(WiredMouse mouse, WiredKeyBoard keyboard) {
        this.mouse = mouse;
        this.keyboard = keyboard;
    }
}
```

**Correct way:**
```java
class MacBook {
    private final Mouse mouse;
    private final KeyBoard keyboard;
    public MacBook(Mouse mouse, KeyBoard keyboard) {
        this.mouse = mouse;
        this.keyboard = keyboard;
    }
}
```

### Example 2:

**Correct way:**
```java
interface Database {
    void save();
}
class MySQLDatabase implements Database {
    public void save() {}
}
class UserService {
    private Database db;

    public UserService(Database db) {
        this.db = db;
    }
}
```
